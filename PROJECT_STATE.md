# pi_gate — состояние проекта (handoff)

Самодостаточная сводка, чтобы продолжить проект в новой сессии или на новой машине, даже если чат
и авто-память не переехали. Если открываешь это как Claude в новой сессии — прочитай и продолжай.
Что за проект и как он устроен — [README.md](README.md). Обновлено: 2026-10-04.

## Окружение разработки

- Машина разработчика — **Linux (CachyOS, на базе Arch)**. Windows не используется.
- Проект: `~/claude_projects/pi_gate` — держать **именно по этому пути**: каталог авто-памяти
  Claude выводится из пути (`~/.claude/projects/-home-<пользователь>-claude-projects-pi-gate/memory/`;
  `/` и `_` превращаются в `-`). Другой путь — память не подхватится.
- Секреты — рядом, **вне репозитория**: `~/claude_projects/pi_gate_private/` (снапшоты малины и
  хопов, слепок `/etc/gate`).
- Git: автор коммитов нейтральный, `gate <gate@localhost>` (репо-локально). Remote `origin` —
  **приватный** репозиторий на GitHub, ветка `master`.
- **В коммитах и комментариях — только плейсхолдеры** вместо реальных IP серверов, VPN-выходов
  и имён хостеров (`<ip-C2>`, `<ip-выхода-VPN>`, `<хостер C2>`). История уже вычищалась один раз.

## Текущее состояние

- Версия `gate` — `0.14s` (`GATE_VERSION` в `_build/gate`).
- Цепочка из 2 хопов: C1 (реле) → C2 (выход). C2 сменён в сентябре 2026: у прежнего выход
  деградировал (исходящие сессии с данными почти все дохли — OpenVPN и SOCKS5 с него не
  поднимались). Новый выход развёрнут без визарда — по шагам `gate-setup` (bootstrap через C1,
  `gate setup redeploy`, запирание `:22` на C1).
- Полосы работают: у каждого устройства свой выход (прямой C2 / OpenVPN / SOCKS5). OpenVPN на
  C2 один — активен ровно один конфиг. Конфиги загружаются файлом через веб-панель
  (`OpenVPN-конфиги`), смена активного перезапускает туннель, не трогая глобальный выход и полосы.
- `gate-clock.service` — после простоя часы малины выставляются по цепочке (у Pi нет RTC).
- Подмена OS-отпечатка (`osfp`) на новом C2 **не включена** — включается вручную:
  `gate osfp on apple` (работает только с VPN-выходом).

## Управление малиной и серверами

- Малина: `ssh pi@raspberry` (алиас в `~/.ssh/config`: `raspberry.local` через mDNS, ключ
  `~/.ssh/pi_gate`). Пользователь `pi` — sudo без пароля.
- Серверы цепочки — **только через C1**, напрямую к C2 не ходить. На малине:
  `sudo python3 /usr/local/bin/chain-render.py exit-cmd /etc/gate/chain.json <<< '<команда>' | sudo bash`.
  Ключ малина→C1 лежит на малине (`mgmt_key` в `/etc/gate/chain.json`), C1→C2 — на C1.
- Скрипты на хопы передавать **через base64**: кавычки не переживают три уровня вложенного ssh.
- Канон — `_build/` + `provision/`. Правишь — в репо, потом заливаешь на малину и сверяешь sha256
  (`/usr/local/bin/gate`, `gate-web.py`, `/usr/local/share/gate/gate-vpn`). `gate-vpn` на C2
  доставляется сам (`ensure_vpn_script` сверяет sha при каждом `vpn_on`).
- Новый VPS под выход — сначала префлайт с C1: проходит ли с него OpenVPN-хендшейк, SOCKS5,
  стабилен ли TCP/TLS. Иначе можно развернуть цепочку на заведомо битом канале.

## Бэклог

1. **Padding** (анти-анализ трафика на плече малина→C1): встроенный xray / cover-traffic
   (`gate-padding` — пока только заглушка в статусе) / padding размеров.
2. **`gate factory-reset`** — полная очистка личного (ключи, chain.json, конфиги xray, web.conf,
   профили, SSID/пароль AP, аренды, история, machine-id, логи) — чтобы передарить малину.
3. Профили носков/PPTP читаются через `eval` — значения не экранируются. Сейчас граница
   закрыта валидацией на входе веб-панели; при случае перевести на безопасный разбор.
4. **Вложенный туннель до C2.** Сейчас цепочка от хопа к хопу: C1 снимает свой слой Reality
   и видит адреса назначения (содержимое HTTPS — нет). Цель — чтобы C1 не знал, куда идёт
   трафик: малина поднимает Reality-сессию прямо с C2, а несёт её внутри туннеля до C1
   (xray `sockopt.dialerProxy`: outbound к C2 ходит через outbound к C1). C1 тогда — тупой
   пересыльщик только на `C2:443`, видит лишь IP малины и шифротекст; C2 видит назначения, но
   не IP малины. Что продумать: полосы — сейчас признак канала переносится через C1 по
   `user`, при вложении канал определится сразу на C2 по uuid его inbound (реле упростится);
   двойное шифрование на малине (Pi 5 должен тянуть — замерить); `chain-render.py` для
   малины и реле, переход без простоя; SSH-управление хопами не меняется.

## Ключевые грабли (не наступать снова)

- `gate-tproxy-up.sh` под `set -e`: любое `$(cat опц-файл)` обязано иметь `|| true`, иначе в
  direct-режиме скрипт падает до создания `GATE_TP` → tproxy лежит → клиенты fail-closed.
- В НЕэкранированных heredoc (`<<PYEOF`) внутри `gate` нельзя писать бэктики и `$()` даже в
  `#`-комментариях python — шелл их выполняет.
- Чужой `.ovpn` с `redirect-gateway def1`: openvpn поднимается с `--route-noexec`, иначе уводит
  маршрут по умолчанию выходного хопа в туннель и хоп теряет связь.
- Кэши, которые обновляются только в одной ветке кода, — главный источник багов этого проекта:
  раскладка DHCP полос (`lanes_dhcp_write`), возможности носка (`socks.caps`), маршрут table 200.
  Меняешь состояние — проверь, кто от него зависит.
- OpenVPN сам переподключается (`ping-restart`) и может пересоздать `tun0` — ядро при этом
  удаляет маршрут table 200. Чинит up-хук `ovpn-up.sh`; не убирать оттуда `ip route replace`.
- Офлайн-установка xray должна класть и `geoip.dat`/`geosite.dat`, иначе конфиг выхода с
  `geoip:private` не проходит `xray -test`, и полосы молча не применяются.
- В zsh `$revs` не разбивается на слова: `git grep … $revs` молча ничего не находит. Сканы
  истории — в bash.
- root не может писать в чужой файл в `/tmp` (`fs.protected_regular`): пусть файл открывает шелл
  пользователя, а root пишет в готовый дескриптор.
- Сразу после переподъёма туннеля `gate exit` / `doctor` может разово показать «—» / `down` —
  холодный старт; перепроверить через несколько секунд, прежде чем чинить.

## Что сохранить при переезде на другую ОС или машину

1. Код — клонировать из приватного GitHub в `~/claude_projects/pi_gate` (тот же путь).
   Бинари xray в git не лежат: `bash provision/fetch-xray.sh` скачает их по SHA из `MANIFEST.txt`.
2. Секреты: `~/claude_projects/pi_gate_private/` — **не** через облако и мессенджеры.
3. Память Claude: `~/.claude/projects/-home-<пользователь>-claude-projects-pi-gate/memory/`
   (при смене имени пользователя — переименовать каталог под новый путь).
4. SSH: `~/.ssh/pi_gate` (малина) и `~/.ssh/github_pi_gate` (GitHub) + блоки `Host raspberry`
   и `Host github.com` из `~/.ssh/config`; права `600`. `raspberry.local` требует mDNS (avahi).
5. Проверка после переезда: `git log`, `ssh pi@raspberry 'gate doctor'`.
